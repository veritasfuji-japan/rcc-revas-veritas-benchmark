## Operational security boundary

The local test patches low-level socket connects to fail, installs a
`httpx.MockTransport` in an `httpx.Client(trust_env=False)`, fixes the
SDK base URL to the official path, and passes a clearly fake API
key. No caller can provide a different `http_client` to this proof.
`max_retries=0`. The MockTransport consumes each of five attempts
before validation. The helper refuses real `OPENAI_API_KEY`,
`TASK4_OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `OPENAI_BASE_URL`,
or database credentials in the process environment. CI secrets
are not imported.

A local dummy client and single-process socket test are NOT an
independently administered egress firewall. Executing this PR grants
no new budget, no real-provider sender permissions, no production
date authority, no independently controlled single-use grant, and no
ability to call a real bank. All prior Provider approvals remain
consumed.

Importantly, the existing `Task4FrozenTransportElement` remains
injectable: an unrelated caller could construct it with a real
provider client. **#320 does not close that deployment security gap.**
The actual protected sender requires a separate root of trust beyond
the writable repository and executable positive IAM, credential,
network and billing denies. The historical two-call budget is NOT
a valid five-call prospective authorization. A five-call scripted
trace does not predict actual model turn count.
