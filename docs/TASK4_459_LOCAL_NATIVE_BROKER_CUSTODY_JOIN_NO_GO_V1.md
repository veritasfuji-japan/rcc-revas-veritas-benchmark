# Task4 #459 — Local Native/Broker integration (research only)

## Goal
Integrate the already merged offline research components #323, #456, #457 and #458 in one local Native A/B replay. This pull request does not change the original implementations or the locked upstream sources.

## Test sequence
1. Execute the original #323 script-generated SDK responses for Arm A and Arm B, independently.
2. Before producing each mock response, record its one-time attempt through the existing #458 broker, using the source request digest.
3. Encrypt the original local HTTP response with #457 before the response is parsed. Store the ciphertext with the same local broker.
4. Return the unchanged response object to the native SDK. Reuse #456 provenance checks and the existing post-only scorer.
5. Restart the broker on the same SQLite database, recover all eight local ciphertext records, verify their request/response hashes, and reject repeat claims.

## Acceptance criteria
- Eight original local SDK response records: four per Arm.
- Two completed **scripted** native terminals and two detached scorer invocations, originating from their own Arm.
- Eight previously consumed slots remain unavailable after the broker process restart.
- Negative tests reject source swaps, altered hashes, incorrect arm/ordinal, forged Provider provenance, and false Utility or dispatch claims.
- Only redacted hashes, test outcomes and a summary are uploaded as CI artifacts.

## Evidence boundaries
The model responses in this test are synthetic, not generated by a model provider. The local broker uses a Unix socket and SQLite on a single GitHub Runner; it does not establish remote atomicity, remote durable storage, independent administration or production security. An ephemeral test recipient key is destroyed at the end. The experimental date is synthetic. Nothing in this PR establishes improved authentic Native Utility.

The separate #455 first-request SDK staging continues to deny external transmission. This PR does not integrate a real model sender, create credentials, enable API billing, or authorize real bank operations.

Issues #321 and #427 remain open and governed by their existing NO-GO decisions. Development CI is read-only, PR-triggered and restricted to the pinned AgentDojo/RCC/VERITAS test sources.
