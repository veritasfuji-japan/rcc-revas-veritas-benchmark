# Task15 standing-order profile controlled runner V1

This additive provider-free in-memory runner connects the frozen prospective rent
profile to pinned RCC review, native VERITAS Bind and native FunctionsRuntime.
It does not modify the frozen Final128 CLI, issuer, original-request validator,
native adapter policy or prior proofs. A profile remains evidence, never dispatch
permission or an authenticated real-user payment mandate.

## Central invariant

The owned harness supplies the complete original request, native current state,
local signing key/registry, generator adapter and benchmark authority fixture.
It issues the fixed ordinal-one rent context before one generator invocation.
The generator receives detached request/state only. The native tool/schema,
source blobs, dependencies and normalized argument identities are fixed.

Unknown raw arguments are refused before normalization. Raw ID is a nonboolean
integer; numeric strings, boolean amounts, integer recurring flags and nested
values are refused. Native normalization adds optional null defaults and maps a
native numeric amount to float; it never changes a recipient, ID or financial
value to match a scorer. One full RCC CandidateAction and immediate prestate are
captured and used by both arms. Native-valid ineligible candidates are retained
in the pair: RCC-only A; B refuses the strict rent profile without repair.

Generation, cancellation, schema or capture failure closes the owned issuer's
local capture slot and prevents another preparation. The frozen issuer has no
public cancellation primitive; this trusted runner closes its process-local
attempt/binding registry under the same issuer lock, without inventing a proposal.
The new tests also check that generator failure cannot later be captured directly.

## Native gates and final sink

Both arms preserve the captured candidate through native RCC review/adoption.
B then requires the registered local profile and strict rent design. Its Bind
constraint callback retains all six existing original-request predicates exactly:
supported_profile, request_authority_bound, exact_argument_shape,
standing_order_id_bound, recipient_bound and amount_bound. Two additional checks
require the registered strict rent design and exact captured candidate. No
existing false predicate is replaced by true. Native adapter policy, Authority,
Constraint, Drift, Risk, candidate/intent binding and postconditions stay required.

The guarded adapter receives one private dispatch token only inside the native
Bind invocation. Before the actual tool callback, the sink rechecks native tool
identity/schema, request, candidate, profile/session, full current prestate, RCC
adoption and live Bind intent/Authority/Constraint/Risk. Admission is thread-bound
and cleared after return; direct/cross-thread/repeated callback attempts refuse.
An attempted sink is closed before final validation. Post-dispatch failures are
infrastructure failures and cannot be reported as safe no-effect or retried.

The positive native transition changes only the selected existing rent recipient
and amount. Subject/date/recurring remain null-defaulted or exactly current;
sender, other schedules, transaction history, balance, user and filesystem remain
unchanged. Native inert false/empty optional values that differ from current state
are still ineligible. All mutations occur on cloned simulator environments; the
owned original snapshot remains unchanged in ordinary execution.

## Evidence and scope

90 dedicated tests exercise positive paired native commits, eight recorded
ineligible common pairs, additional native-inert optional negatives, preservation
of explicit current optional values, unsupported raw shapes, cancellation and
issuer-slot closure, current-state ambiguity, RCC refusal/replacement, every
legacy predicate, native Bind gates, fifteen late sink substitutions, intent
drift, direct/cross-thread/duplicate callbacks, immutable captures, one winner in
32 parallel arm attempts/preparations and post-dispatch failures.

Provider/SDK/network/database, native scorer/ground truth and external evidence
writes are forbidden in new tests. The prior 101 rent-profile / 73 rent-design /
28 observer / 32 wire / 40 trajectory / 65 address-runner / 101 address-profile /
91 mapping proofs and fixed reports are reproduced. Earlier diagnostic scorer
results remain downstream observations and never enter this runner's authority.

The audit reexecutes the pinned native tool on detached environments and checks
recorded native returns, full pre/poststates, full RCC/control hashes, identical
RCC reviews, Bind gate receipts, unmodified legacy predicate values, final sink
events and the eight A-dispatch/B-no-dispatch refusal pairs. Fresh signatures,
session IDs, pairing hashes containing local context, decision times and receipt
IDs are not claimed byte-identical; deterministic reports are compared.

The controlled admission is bounded to one existing rent update and an owned
benchmark authority signal. Real user/ledger/beneficiary authenticity, global
durability, clocks/expiry/revocation and infrastructure-wide bypass resistance
remain outside this proof. Earlier address execution and a full ordered Task15
trajectory are not established. Refund/date/password authority is not supplied.
Profile_itself_execution_permission=false; full_task15_admissible=false.
Historical issuance/recovery, existing-runner safe-to-relax, provider/database
execution, scorer/gold-derived authority, repair and V13 reuse remain zero.
Utility recovery, injection remeasurement, external/held-out validation and
production readiness are not claimed.
