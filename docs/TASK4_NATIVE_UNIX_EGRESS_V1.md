# Closed Native SDK over Unix HTTP with all-actor IP rejection

This disposable CI-only profile joins actual frozen Native SDK serialization,
preissued synthetic Ed25519 grants, separate-UID Custody single-use consumption,
the pinned real VERITAS Bind core, eight scripted backend effects, AEAD custody
and return to SDK parsers under a strict eight-UID IPv4/IPv6 output rejection
policy. It does not run on or enroll the operator VM, contact a Provider, deploy
host policy or grant live execution permission.

## Why a new transport profile

The existing closed Native proof uses Custody-to-backend TCP. Rejecting all IP
output for Custody 61106 and backend 61103 would block that valid path as well.
This profile injects only a fixed local HTTP-over-AF_UNIX transport and server
constructor into the unchanged `task4_native_os_custody_v1` research functions.
It does not replace SDK, signature, scope, consume, Bind, backend validation or
AEAD functions. The frozen Native module SHA remains
`b1fb7b407b3c4eaa24ecc9e0746cae9bf4b6cfdb2e379b6f6687bdca17be038d`.
The new module and exported tracked source are independently hashed in reports.

The local HTTP client pins the backend socket peer to UID 61103. The backend
accepts only UID 61106 via SO_PEERCRED before parsing HTTP. Existing synthetic
HMAC request authentication remains mandatory. There is no DNS/TCP fallback,
remote endpoint selection, arbitrary method routing or mutation retry. This
transport is not mTLS, a public HTTPS identity or a replacement for the future
Provider transport. Native UID 61101 still reaches Custody via its existing
peer-checked Unix protocol and cannot read Custody/backend credentials.

## Joined experiment

Root verifies exact external AgentDojo/RCC/VERITAS git pins, exports tracked
sources to a protected disposable tree, and starts a new network namespace with
loopback only. The parent namespace identity is checked before raising lo; the
child then verifies root, a live distinct parent namespace, pinned frozen source
and loopback-only links before nft mutation. No host table is installed. Only
synthetic fixture keys are generated, in unused disposable numeric UIDs. The
runner refuses any already allocated target UID, so this is not a VM migration
or a way to reuse the operator's retained keys/accounts.

All eight roles 61101 through 61108 are denied for all IPv4/IPv6 output including
loopback and DNS: agent, executor, backend, stranger, issuer, Custody, archive and
runtime. This is a strict superset of the five UIDs in the successful operator
host trial, not the same installed table or a completed host-lease integration.
Every target UID has four real TCP/UDP IPv4/IPv6 successes before policy, then
four denials joined individually to increased kernel counters both before and
after the Native run. Root's four banner controls continue to succeed. The full
installed table/chain/eight-rule grammar is retained and validated. After
fixture-only deletion all 32 target flows must succeed again.

Seven non-Custody UIDs also attempt the backend Unix socket. They must observe
refusal, and the backend must independently record the same peer UID set with
zero effects before the positive run. Custody is trusted within this profile:
a compromised Custody with its synthetic transport key is not proven unable to
bypass Bind. The kernel peer test does not turn transport identity into authority.

While the policy remains installed, the original frozen Native research code
runs A/B four SDK requests each. The original scope remains eight prelisted
requests. Each request passes the unchanged signature/scope checks, durable
SQLite consume, real Bind BLOCKED/zero-apply then COMMITTED/one-apply, authenticated
Unix backend, and AEAD commit before returning bytes to SDK parsers. Exact hashes
join the Native request, backend receipt, consume row, Bind record, ciphertext
and transport POST body. Both scripted Native terminals/scorer calls and eight
replay denials are required. The local scripted scorer result is not measured
real-model Utility.

## Evidence and boundaries

A full report and a 15-check zero-skip integration JUnit record are retained in
the existing pinned Native CI workflow, alongside portable strict-parser tests.
`validate` replays policy grammar, real flow/counter coverage, Unix peer refusals,
actual frozen SDK/lineage/scorer joins, pinned Bind blob and receipt hashes,
single-use rows and ciphertext joins. Source pins and current commit must match.
The supervisor deletes only its table inside the disposable namespace and stops
all fixture services; exceptional outer termination kills the dedicated child
process group. Parent table names are a limited negative control, not complete
host policy-content or independent runtime attestation.

This profile uses the fixed eight-request Native path with agent UID 61101. The
bounded-history runtime UID 61108 is included in network refusal probes but is
not the running Native driver here. The retained GitHub-backed signed-ledger
service, bounded-history admission, raw HTTP-before-parser archive profile,
separate archive-role execution, operator host 15-second lease and independent
administration are not joined by this change. Response AEAD is committed by
Custody as in the reused research profile; the publicly reproducible test
recipient does not establish real-data confidentiality. Those limits stay
explicit in every report.

The next operator-stage integration needs a separately reviewed enrollment and
transport design for retained service UID 109 and those Native roles. Do not run
this disposable initializer on the prepared VM or infer live permission from CI.
