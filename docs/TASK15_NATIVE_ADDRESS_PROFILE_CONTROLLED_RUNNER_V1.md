# Task15 native address profile controlled runner V1

This round connects the #216 street/city mapping and #217 locally registered,
pre-generation request profile to actual pinned RCC, native VERITAS Bind and the
AgentDojo FunctionsRuntime. It is a separate, provider-free controlled runner.
The frozen Final128 runner, original request validator, resolver and historical
artifacts are unchanged.

The central invariant is that B can dispatch only the exact first normalized
address candidate captured against the independently owned complete request and
immediate pre-state. The profile is evidence; every upstream RCC and native Bind
gate must pass independently, and the live state, candidate and native definition
must still match at the effect sink.

## One candidate and two arms

`prepare` verifies the loaded native source, tool implementation, argument schema,
account dependency, environment class and dependency versions. The harness then
issues a profile before invoking its generator once. The generator receives only
the complete request and detached pre-state. Native normalization adds the inert
null name defaults; it does not repair address values or remove unknown arguments.

The immutable full RCC CandidateAction and V1.1 control identity are captured
once. A pair identity additionally binds the authenticated context digest. A and
B use detached native environments from the same serialized immediate pre-state.
The context remains evidence, with execution permission false.

Six normalized but ineligible candidates are retained in the common population:
full-line city, attacker city, wrong street, first-name change, last-name change
and null city. Each reaches the same RCC review in A/B. A retains RCC-only
admission; B refuses without native dispatch. Unsupported tools, nested calls,
unknown arguments, message/metadata/content proposals and non-native value types
terminate preparation. No scorer, label, repair or retry selects the pair.

Issuance closes the runner's case/ordinal after any generation exception,
cancellation or structural failure. No prepared execution record is created on
those failures. The evidence session's low-level APIs remain harness-owned;
this runner does not claim to revoke every registry entry globally.

## Native gates and the final sink

The actual NativeGovernanceHook reviews both arms. An RCC rejection remains a
rejection. Even an adopted candidate with a valid replacement hook hash must
match the immutable common capture exactly; this runner never adopts a repaired
replacement into the pair.

B verifies the owned profile after RCC, then builds the existing benchmark
ExecutionIntent and actual AgentDojoBankingBindAdapter. The frozen Task15 request
validator must return exactly its existing five address predicates. Only
`city_bound` is composed with the authenticated, exact street/city projection.
`supported_profile`, `request_authority_bound`, `exact_argument_shape` and
`street_bound` remain unchanged. Any new or differently typed predicate closes
the path. Task policy, preregistered tool, candidate hash, Authority fixture,
state drift and runtime risk remain native adapter/Bind checks.

The guarded adapter receives a transient dispatch token through Bind's existing
post-adjudication dispatch hook. Direct adapter apply before that hook, retained
apply after Bind and direct mutation callbacks outside the admitted thread are
refused. At apply and again at the native sink, it checks the exact intent, live
state fingerprint, Authority, constraints, risk, profile, candidate and loaded
native tool. A single sink attempt is recorded before those final checks. Each
arm has one local attempt; 32 concurrent B attempts yield one commit and 31
rejections. An idempotent address write cannot hide a second native dispatch.

Normal B execution uses the actual pinned native function. Its postcondition is
the exact whole-environment transition: street/city change and everything else,
including names, password, files, bank state and transactions, is preserved.
Post-dispatch failures propagate as infrastructure/integrity failures. No
rollback, no-effect or attack-prevention success is inferred from a failed call.

## Evidence and limits

The dedicated audit first reproduces #217, #216 and their frozen historical
diagnosis dependencies. It then verifies clean pinned external checkouts,
actual loaded import paths and local source blobs; runs 65 native tests with
provider clients, network, database, trustlog writes and scorers denied; and
audits the positive pair, six refusal pairs and 32-way replay evidence.

The positive fixture is a fresh scripted Boston request and synthetic native
environment. It is not a provider trajectory or an original AgentDojo task run.
No profile is retroactively attached to the five historical Task15 candidates.
The historical diagnosis remains five projection matches and zero recoveries.
The earlier 81/12/69 result and 22 binding mismatches are unchanged.

The HMAC, local registry and final sink assume an independently owned Python
harness, acquisition source, request/state, code, key, policy, gate and generator
outside agent/tool reach. They do not authenticate a real user or external
pre-state and do not protect against arbitrary trusted-process compromise.
There is no durable/global exactly-once guarantee or new clock/expiry/revocation
claim. Native Bind's existing timestamps and TTL semantics remain in use.

This admission is limited to `update_user_info` street/city. It creates no
standing-order, refund, date, password, Task13 or other-task authority. Region and
ZIP remain evidence; native storage has no separate fields for them. Complete
postal-address storage and full Task15 admissibility are not proven.

Provider execution, database access, scorer/gold-derived authority, V13 reuse
and external effects are zero. Utility recovery, injection success remeasurement,
held-out generalization, independent external validation and production readiness
are not claimed. The existing Final128 runner stays frozen.
