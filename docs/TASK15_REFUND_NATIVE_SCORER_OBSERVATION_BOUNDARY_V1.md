# Task15 refund native scorer observation boundary V1

The additive observer accepts only detached completed #238 A/B protected-call
records. It verifies both terminal outcomes, full normalized candidate and
pairing, request/pre-state/case/ordinal linkage to the exported signed scope,
exact refund-only native state transition and native return, journal order,
actual local Bind receipt linkage and consumption-before-native-call record.
B consumption remains UNKNOWN without effect/no-effect authority or retry.
Invalid or partial native failure evidence is rejected before rubric lookup.

An exported signature is verified relative to its exported root for record
consistency only. This does not authenticate the original registry or external
root/principal/ledger/clock, and does not constitute current execution permission.
Repeated observation after revocation reads past evidence; it never reissues or
revalidates live authority. Caller owns completed evidence acquisition.

Only after both records pass validation does the observer load the actual pinned
Task15 and InjectionTask0 rubrics. Each arm receives detached native pre/post
states. There is no completed pipeline conversation in #238, so model output and
functions-stack-trace inputs are explicitly empty; no assistant text or invented
history is added. The output is labelled a refund-only state-rubric development
diagnostic. An owned request differing from native Task15 PROMPT is separately
labelled diagnostic. Whole trajectory scoring, whole Task15 execution, new
Final128 Utility and injection success measurement remain false.

The observer has no issuer/store/RCC/Bind/generator/native runtime interface.
Strict boolean utility/security output is checked. Scorer exceptions,
cancellation, malformed output or mutation of detached inputs stop observation
without retrying scoring or execution or changing the original record/store.
Even true diagnostic scores cannot admit a refused candidate. The native scorer
is trusted pinned code, not a sandbox for arbitrary Python closures. No
confinement of callback code with independent outside references is claimed.

The 85-test population includes 12 observed pairs: native refund-only and Boston
request diagnostic (both A/B local commit), eight candidate mismatches, one actual
Bind refusal, and one fixed diagnostic proposal sent by A to a specified recipient
with subject Spotify and refused by B. The last proposal intentionally yields a
true native InjectionTask0 goal for A and false for B; it is not a model attack
trial or a new injection success rate. All 24 native Task15 utility observations
are false because refund-only state does not complete the address and rent goals.
The fixed diagnostic proposals precede rubric access and are never repaired from
scores or used to create authority.

The remaining tests cover 45 invalid evidence cases rejected before rubric
lookup, 24 arm-specific scorer mutation/failure/cancellation cases, fake positive
scores, forbidden dispatch/authority/store callbacks, repeated readonly
observation and incomplete post-append failure. The audit separately replays all
12 actual RCC/Bind pairs with fresh keys/root/registry/store, independently invokes
native scoring on 24 detached arm states, and recomputes all 45 evidence refusals.
It reproduces the 1,516 previous dedicated tests and pins their report bytes.

Provider/client/database/scorer-derived authority/candidate repair/V13 reuse are
zero. No measured Utility recovery, full Task15/Final128 trajectory integration,
external payment/effect reconciliation, durable global uniqueness/restart,
external or held-out validation, or production readiness is claimed.
